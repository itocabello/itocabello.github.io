Generación de los ficheros en HDFS

Durante el proceso de ingesta, Apache Flume almacena la información en HDFS generando automáticamente ficheros de salida con el prefijo accidentes24.

Este comportamiento forma parte del mecanismo interno de escritura de Flume, que puede generar múltiples archivos como resultado del proceso de transferencia.

Posteriormente, estos ficheros pueden ser procesados mediante trabajos MapReduce o Hadoop Streaming, ya que HDFS permite trabajar con el conjunto de datos independientemente de la fragmentación física de los archivos.

Ejercicio resuelto: ingesta con Flume

El funcionamiento del agente puede resumirse mediante las siguientes etapas:

1. Incorporación del fichero flume_accidentes.conf al directorio flume del Namenode.

El usuario copiara el fichero analizado en el punto anterior denominado flume_accidentes.conf,en el directorio /usr/local/flume/conf/

Copiar fichero flume_accidentres.conf al directorio indicado

2. Iniciar el agente de Apache Flume desde el contenedor Namenode.

Dentro del contenedor Namenode, sudo docker exec -it namenode /bin/bash y tras el punto 1 anterior, se procede a iniciar el agente flume, mediante el comando mostrado a continuación. La instrucción inicia Apache Flume utilizando el agente denominado agent y la configuración definida en el fichero flume_accidentes.conf. 

agent.sinks.sink1.type = hdfs
--name agent \
--conf /usr/local/flume/conf \
--conf-file /usr/local/flume/conf/flume_accidentes.conf \
-Dflume.root.logger=INFO,console
Consultar Iniciar Agente Flume en Jupyter.
3. Incorporación del fichero a cargar en HDFS.

Una vez iniciado el agente, para verificar que todo funciona correctamente, el usuario copiara el fichero TABLA_ACCIDENTES_24.csv en el directorio monitorizado /home/hadoop/flume_input. 

cp /media/notebooks/dataset/TABLA_ACCIDENTES_24.csv /home/hadoop/flume_input
4. Detección del archivo.

La Source detecta automáticamente el nuevo archivo incorporado al directorio monitorizado.

3. Generación de eventos.

Los registros del fichero son transformados en eventos Flume.

4. Almacenamiento temporal.

Los eventos son almacenados temporalmente en el Channel.

5. Transferencia a HDFS.

El Sink recupera los eventos y los transfiere al sistema de archivos distribuido HDFS.

6. Disponibilidad de los datos.

Los datos quedan disponibles en HDFS para su posterior análisis mediante Hadoop Streaming y MapReduce.

Conclusión

La configuración desarrollada permite automatizar la ingesta de información desde el sistema de archivos local hacia HDFS. Apache Flume actúa como mecanismo de transferencia basado en eventos, conectando la fuente de datos local con el sistema de almacenamiento distribuido.

De esta manera, el estudiante puede observar de forma práctica el recorrido de los datos desde el fichero TABLA_ACCIDENTES_24.csv hasta su almacenamiento en HDFS y su posterior disponibilidad para tareas de procesamiento distribuido.

Referencia

Esta práctica se encuentra relacionada con el apartado correspondiente a la ingesta de datos mediante Apache Flume y con la arquitectura Hadoop desarrollada en el proyecto.
