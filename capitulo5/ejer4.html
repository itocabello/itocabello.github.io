Ejercicio resuelto. Preparación del entorno para la ingesta de datos con Apache Flume

En este ejercicio se configura el entorno necesario para automatizar la ingesta de datos en el clúster Hadoop mediante Apache Flume. El objetivo es que el estudiante comprenda cómo transferir información desde el sistema de archivos local hasta HDFS de forma completamente automática.

Antes de comenzar este ejercicio, se recomienda revisar la lección teórica dedicada a Apache Flume, donde se describen su arquitectura, funcionamiento y los componentes principales (Source, Channel y Sink).
Consultar características de Apache Flume
Durante esta práctica se configurará un agente Flume encargado de monitorizar automáticamente un directorio local y transferir los nuevos archivos al sistema de almacenamiento distribuido HDFS.

Aplicación en este proyecto

En la infraestructura desarrollada para este proyecto, Apache Flume será el encargado de automatizar la transferencia del conjunto de datos TABLA_ACCIDENTES_24.csv desde el sistema de archivos local hasta el sistema distribuido HDFS.

El agente Flume se ejecutará sobre el contenedor NameNode, donde supervisará continuamente un directorio compartido. Cada vez que aparezca un nuevo fichero, éste será enviado automáticamente al clúster Hadoop para su posterior procesamiento mediante Hadoop Streaming, MapReduce y Apache Hive.

Objetivo del ejercicio

La finalidad de esta práctica consiste en automatizar el proceso de carga de datos utilizando Apache Flume. Para ello se configura un agente capaz de detectar la llegada de nuevos ficheros al sistema local y transferirlos automáticamente al clúster Hadoop, sin necesidad de intervención manual.

El estudiante comprenderá el funcionamiento interno de un flujo de datos basado en eventos y la función que desempeña cada componente de Apache Flume dentro de una arquitectura Big Data.

Conjunto de datos utilizado

Como caso práctico se utilizará el fichero TABLA_ACCIDENTES_24.csv, correspondiente a los microdatos oficiales de accidentes con víctimas publicados por la Dirección General de Tráfico.

Tal y como se explicó en el apartado 5.2.3, el fichero ha sido descargado previamente desde la fuente oficial y almacenado en el directorio: 

    /media/notebooks/dataset

Este directorio está compartido con el contenedor NameNode, permitiendo que Apache Flume pueda acceder directamente al fichero para iniciar su proceso de ingesta.

Arquitectura del flujo de ingesta

Apache Flume basa su funcionamiento en un flujo de datos orientado a eventos. Durante esta práctica el agente monitoriza continuamente un directorio del sistema de archivos local y, cuando detecta un nuevo fichero, inicia automáticamente su transferencia hacia HDFS.

Configuración del agente Apache Flume

Una vez definido el objetivo de la ingesta de datos mediante Apache Flume, es necesario configurar el agente encargado de realizar el proceso de transferencia desde el sistema de archivos local hasta HDFS.

La configuración se realiza mediante un fichero de propiedades denominado flume_accidentes.conf, en el que se definen los componentes que forman parte del flujo de datos y las relaciones existentes entre ellos.

Configuración del agente Apache Flume mediante el fichero flume_accidentes.conf. Fuente: elaboración propia.

Componentes del agente Flume

1. Source

Representa el punto de entrada de los datos.

  • Tipo spooldir.
  • Monitoriza un directorio local: /home/hadoop/flume_input
  • Detecta automáticamente nuevos ficheros.
  • Transforma el contenido en eventos.
2. Channel

Actúa como almacenamiento temporal entre Source y Sink.

  • Canal tipo memory.
  • Alta velocidad de transferencia.
  • Desacopla la recepción y escritura.
  • Garantiza el flujo continuo de eventos.
3. Sink

Destino final de los datos procesados.

  • Tipo HDFS.
  • Escribe directamente en Hadoop.
  • Formato Text / DataStream.
  • Preparado para Hadoop Streaming.

Relación entre los componentes

Una vez definidos todos los elementos del agente, es necesario establecer la comunicación entre ellos para completar el flujo de datos.

La Source puede publicar eventos sobre uno o varios canales, mientras que cada Sink consume los eventos de un único Channel. Esta arquitectura proporciona una gran flexibilidad para diseñar distintos flujos de ingesta adaptados a las necesidades del ecosistema Hadoop.

Conclusión

Una vez finalizada esta práctica, el estudiante dispondrá de un agente Apache Flume completamente operativo capaz de automatizar la incorporación de datos al sistema HDFS. Esta infraestructura servirá como punto de partida para los siguientes ejercicios, en los que los datos almacenados serán procesados mediante Hadoop Streaming, MapReduce y el resto de tecnologías que integran el ecosistema Hadoop.
