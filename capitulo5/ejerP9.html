Ejercicio resuelto: Explotación de datos de calidad del aire mediante Apache Hive

En este ejercicio se propone utilizar Apache Hive para realizar consultas sobre un conjunto de datos abiertos correspondiente a la calidad del aire de Madrid. El objetivo es aplicar los conocimientos adquiridos sobre el ecosistema Hadoop, especialmente sobre HDFS, Hive y el lenguaje de consultas HiveQL.

El conjunto de datos se descarga inicialmente desde el entorno Jupyter Notebook y posteriormente se almacena en el sistema de archivos distribuido HDFS. Una vez disponible en HDFS, los datos pueden ser registrados mediante una tabla de Apache Hive y explotados mediante consultas SQL.

Este ejercicio permite al estudiante comprobar cómo una fuente de datos externa puede incorporarse al ecosistema Hadoop y ser posteriormente consultada mediante una interfaz SQL, sin necesidad de desarrollar directamente programas MapReduce.

Objetivo del ejercicio

El objetivo principal consiste en familiarizar al estudiante con el proceso completo de incorporación y explotación de un conjunto de datos abiertos mediante Apache Hive.

Durante el ejercicio se trabajan las siguientes fases:

  • Descarga del conjunto de datos desde Jupyter Notebook.
  • Almacenamiento del fichero CSV en HDFS.
  • Creación de una base de datos en Hive.
  • Creación de una tabla para almacenar los datos.
  • Consulta de los registros mediante HiveQL.
  • Agrupación de los datos por magnitud.
  • Identificación de los contaminantes presentes en el conjunto de datos.
  • Análisis de la cantidad de registros disponibles para cada magnitud.

1. Conjunto de datos utilizado

Para realizar el ejercicio se utiliza un conjunto de datos correspondiente a las mediciones de calidad del aire de Madrid. El fichero se encuentra almacenado en HDFS en la siguiente ubicación:

/dataset/calidad_aire_madrid/calidad_aire_madrid.csv

El fichero contiene información relativa a las estaciones de medición, las magnitudes contaminantes y los valores horarios registrados durante cada día.

Entre los principales campos disponibles se encuentran:

MAGNITUD Código de la magnitud contaminante medida.

2. Creación de la base de datos en Apache Hive

Una vez disponible el fichero en HDFS, se accede al servidor Hive mediante Beeline. En este ejercicio, las operaciones de creación de la base de datos y de las tablas se realizan desde el cliente Beeline. 

beeline -u jdbc:hive2://localhost:10000

A continuación se crea la base de datos destinada a almacenar la información de calidad del aire: 

CREATE DATABASE IF NOT EXISTS calidad_aire;
    
    USE calidad_aire;

De esta forma se dispone de un espacio lógico independiente dentro de Hive para realizar las consultas sobre el conjunto de datos.

3. Creación de la tabla de calidad del aire y magnitudes

Una vez creada la base de datos, se definen las tablas que permitirá consultar el fichero CSV mediante HiveQL. La estructura de la tabla reproduce los principales campos disponibles en el conjunto de datos.

Entre ellos destacan la estación de medición, la magnitud contaminante, la fecha y los valores correspondientes a las diferentes horas del día.

Además, los datos de la tabla de calidad del aire serán cruzados con los datos de la tabla maestra magnitudes para detallar los tipos de magnitudes a explotar.

Importante: En la infraestructura utilizada en este proyecto, la creación y modificación de las tablas Hive se realiza desde Beeline utilizando Jupyter Notebook para ejecutar las instrucciones de Beeline y visualizar sus resultados.

5. Consulta de las magnitudes disponibles

Una vez creada y cargada la tabla, se puede utilizar HiveQL para comprobar qué magnitudes aparecen en el conjunto de datos y conocer el número de registros asociados a cada una. 

SELECT MAGNITUD,
           COUNT(*) AS registros
    FROM datos_calidad_aire
    GROUP BY MAGNITUD
    ORDER BY MAGNITUD;

Esta consulta utiliza la cláusula GROUP BY para agrupar los registros según el código de magnitud y la función COUNT() para obtener el número de registros disponibles para cada contaminante.

6. Interpretación de las magnitudes mediante HiveQL

Para facilitar la interpretación de los resultados, se puede utilizar la expresión CASE de HiveQL para transformar el código numérico de la magnitud en el nombre del contaminante correspondiente. 

SELECT
        MAGNITUD,
    
        CASE MAGNITUD
            WHEN 1 THEN 'Dióxido de Azufre (SO2)'
            WHEN 6 THEN 'Monóxido de Carbono (CO)'
            WHEN 7 THEN 'Monóxido de Nitrógeno (NO)'
            WHEN 8 THEN 'Dióxido de Nitrógeno (NO2)'
            WHEN 9 THEN 'Partículas < 2.5 µm (PM2.5)'
            WHEN 10 THEN 'Partículas < 10 µm (PM10)'
            WHEN 12 THEN 'Óxidos de Nitrógeno (NOx)'
            WHEN 14 THEN 'Ozono (O3)'
            WHEN 20 THEN 'Tolueno (TOL)'
            WHEN 30 THEN 'Benceno (BEN)'
            WHEN 35 THEN 'Etilbenceno (EBE)'
            WHEN 37 THEN 'Metaxileno (MXY)'
            WHEN 38 THEN 'Paraxileno (PXY)'
            WHEN 39 THEN 'Ortoxileno (OXY)'
            WHEN 42 THEN 'Hidrocarburos totales (hexano)'
            WHEN 43 THEN 'Metano (CH4)'
            WHEN 44 THEN 'Hidrocarburos no metánicos (hexano)'
            WHEN 431 THEN 'Metaparaxileno (MPX)'
            ELSE 'Magnitud desconocida'
        END AS contaminante,
    
        COUNT(*) AS registros
    
    FROM datos_calidad_aire
    
    GROUP BY MAGNITUD
    
    ORDER BY registros DESC;

De esta forma, el resultado obtenido por Hive resulta más sencillo de interpretar, ya que cada código aparece asociado al nombre del contaminante correspondiente.

7. Consulta de una magnitud concreta

Como ejercicio adicional, se puede seleccionar una magnitud concreta para analizar sus mediciones. Por ejemplo, el código 8 corresponde al dióxido de nitrógeno (NO₂). 

SELECT
        PROVINCIA,
        MUNICIPIO,
        ESTACION,
        MAGNITUD,
        ANO,
        MES,
        DIA,
        H01,
        H02,
        H03,
        H04,
        H05,
        H06,
        H07,
        H08,
        H09,
        H10,
        H11,
        H12,
        H13,
        H14,
        H15,
        H16,
        H17,
        H18,
        H19,
        H20,
        H21,
        H22,
        H23,
        H24
    FROM datos_calidad_aire
    WHERE MAGNITUD = 8
    LIMIT 20;

Esta consulta permite observar cómo se distribuyen los valores horarios de un contaminante concreto y constituye un punto de partida para realizar posteriormente análisis más avanzados.

8. Ejecución desde Jupyter Notebook

Aunque las operaciones se realizan mediante el cliente Beeline, las instrucciones pueden ejecutarse desde Jupyter Notebook utilizando comandos del sistema. Por ejemplo: 

!beeline -u jdbc:hive2://localhost:10000 -e "
    USE calidad_aire;
    
    SELECT MAGNITUD, COUNT(*) AS registros
    FROM datos_calidad_aire
    GROUP BY MAGNITUD
    ORDER BY registros DESC;
    "

El resultado de la consulta se muestra directamente en la salida de la celda de Jupyter, permitiendo al estudiante comprobar de forma práctica el funcionamiento de HiveQL sobre los datos almacenados en Hadoop.

9. Conclusiones del ejercicio

La realización de este ejercicio permite comprobar cómo Apache Hive facilita la explotación de grandes conjuntos de datos almacenados en HDFS mediante un lenguaje basado en SQL.

A partir del conjunto de datos de calidad del aire de Madrid, el estudiante ha realizado el proceso completo de incorporación de información externa al ecosistema Hadoop, desde su almacenamiento en HDFS hasta su consulta mediante HiveQL.

Además, la utilización del campo MAGNITUD permite introducir operaciones de agrupación, recuento y clasificación de los datos, relacionando los códigos existentes en el fichero con los diferentes contaminantes atmosféricos.

Este ejercicio complementa los trabajos realizados anteriormente con HDFS, MapReduce, Hadoop Streaming y otros componentes del ecosistema, mostrando una alternativa basada en consultas declarativas para el análisis de información almacenada en un entorno Big Data.
