Ejercicio Final 2: Levantar contenedor db_cluster – MySQL¡

Despliegue de MySQL para la explotación de los datos generados durante el procesamiento Hadoop.

Objetivo del ejercicio

El ejercicio tiene como finalidad aplicar un proceso de anonimización sobre los documentos clínicos de MEDDOCAN, procesarlos mediante Python 3 y Hadoop Streaming, generar un fichero estructurado en formato CSV y prepararlo posteriormente para su incorporación a una base de datos MySQL.

Una vez finalizados los procesos de procesamiento y transformación de los datos mediante el clúster Hadoop, se puede utilizar un contenedor independiente para almacenar y explotar los resultados mediante una base de datos relacional.

En este ejercicio se propone levantar el contenedor db_cluster, basado en MySQL, utilizando los ficheros .csv generados durante las etapas anteriores del proyecto.

El objetivo es completar el flujo de procesamiento de los datos, desde su generación en el clúster Hadoop hasta su almacenamiento estructurado en una base de datos MySQL.

Arquitectura del despliegue

La siguiente figura muestra la arquitectura que será desplegada cuando sea necesario utilizar un contenedor con MySQL y realizar la carga de los datos compartidos en formato .csv.

1. Traslado del fichero CSV

Lo primero que debemos realizar antes de levantar el contenedor db_cluster es trasladar los datos del fichero .csv generado por el clúster Hadoop.

El fichero se encuentra inicialmente en el directorio compartido:

/media/notebook

Este fichero deberá copiarse al directorio utilizado por db_cluster para realizar la carga de los datos:

/home/uned/ClusterUned/db_cluster/dataset
Objetivo

El fichero CSV debe estar disponible en el directorio dataset antes de realizar la construcción de la imagen Docker.

1. Preparación de los documentos.

Una vez cargados los ficheros .txt que se desean anonimizar, se prepara el fichero que permitirá agrupar los campos procesados. En este ejercicio se utilizará el nombre:

meddocan_anonimizado.txt
2. Selección de los campos a anonimizar.

En el anexo del ejercicio se han establecido inicialmente los siguientes campos para el proceso de anonimización:

  • nombre
  • apellidos
  • CIPA
  • domicilio

El estudiante puede ampliar posteriormente esta lista incorporando otros campos que considere necesario anonimizar.

3. Ejecución del script de anonimización.

Una vez preparados los documentos, se ejecuta el script mediante Python 3 y Hadoop Streaming.

!python3 meddocan_anonymization.py -r hadoop hdfs:///dataset/meddocan-hdfs/*txt > meddocan_anonimizados.txt

Figura 44. Ejecución del trabajo MapReduce para la anonimización de los documentos MEDDOCAN sobre el clúster Hadoop. Fuente: elaboración propia.

Ejecución del trabajo MapReduce

La figura muestra la ejecución del trabajo de anonimización mediante Hadoop Streaming sobre el clúster Hadoop. Durante el procesamiento se observa la evolución de las tareas Map y Reduce, así como el porcentaje de progreso alcanzado en cada una de las fases.

El trabajo procesa los documentos clínicos almacenados en HDFS y distribuye las diferentes tareas entre los recursos disponibles del clúster. El Mapper analiza los documentos y aplica las reglas de anonimización definidas en el programa Python, mientras que la fase Reduce consolida los resultados generados por las distintas tareas.

Una vez finalizado el procesamiento, Hadoop muestra el estado de finalización del trabajo y la información asociada a las tareas ejecutadas. De esta forma, el estudiante puede comprobar de manera práctica cómo un conjunto de documentos puede ser procesado de forma distribuida mediante el modelo MapReduce.

Importante: El proceso de anonimización puede tardar varios minutos, dependiendo del número de documentos y de los recursos disponibles en el clúster Hadoop.
4. Ejecución del trabajo MapReduce.

Una vez lanzada la instrucción, Hadoop Streaming inicia el trabajo MapReduce sobre el clúster desplegado en la infraestructura contenerizada. Los documentos son divididos en diferentes fragmentos o splits, que son distribuidos entre los nodos disponibles para su procesamiento paralelo.

5. Aplicación de las reglas de anonimización.

Las tareas Map analizan las diferentes partes de los documentos y aplican las reglas definidas en el script, identificando y sustituyendo los elementos que pueden contener información sanitaria protegida o datos potencialmente identificativos.

6. Generación del fichero anonimizado.

Una vez finalizado el procesamiento, todos los resultados se agrupan en el fichero:

meddocan_anonimizados.txt

Conversión del resultado a formato CSV

Una vez finalizado el proceso de anonimización y procesados todos los documentos .txt, se dispone de un único fichero que contiene los resultados obtenidos.

Para facilitar la carga de estos datos en una base de datos relacional, es necesario transformar el fichero meddocan_anonimizados.txt al formato CSV.

Script convertir_txt_csv.py

Para realizar esta transformación se ha desarrollado el script convertir_txt_csv.py, incluido igualmente en el anexo de código de ejercicios.

!python3 convertir_txt_csv.py meddocan_anonimizados.txt meddocan_anonimizados.csv

Resultado de la conversión

Al finalizar el proceso se obtiene el fichero:

meddocan_anonimizados.csv

Este archivo contiene la información anonimizada y estructurada en formato CSV, preparada para su posterior incorporación a la base de datos MySQL.

Incorporación de los datos a MySQL

Una vez generado el fichero CSV, este debe estar disponible en el volumen compartido del clúster, concretamente en /media/notebooks, para que pueda ser utilizado posteriormente en el proceso de carga de la base de datos.

El fichero será migrado al directorio utilizado por el contenedor db_cluster, que será el responsable de cargar los datos y proporcionar la infraestructura necesaria para su almacenamiento estructurado.

Directorio utilizado por el contenedor

/home/uned/ClusterUned/db_cluster/dataset

Desde este directorio se podrá acceder al fichero CSV generado durante el proceso de anonimización y utilizarlo para poblar la base de datos MySQL.

Flujo completo del ejercicio

  1. Carga de los documentos clínicos .txt de MEDDOCAN.
  2. Preparación de los campos que serán anonimizados.
  3. Ejecución del script meddocan_anonymization.py.
  4. Procesamiento distribuido mediante Hadoop Streaming y MapReduce.
  5. Generación del fichero meddocan_anonimizados.txt.
  6. Conversión del fichero TXT a CSV.
  7. Generación del fichero meddocan_anonimizados.csv.
  8. Preparación del fichero para su incorporación a MySQL.

Conclusiones

El ejercicio permite comprobar de forma práctica cómo una arquitectura Big Data basada en Docker y Hadoop puede utilizarse para procesar documentos clínicos de forma distribuida.

El empleo de Python 3 mediante Hadoop Streaming facilita la implementación de las tareas de procesamiento, mientras que el modelo MapReduce permite distribuir la carga de trabajo entre los diferentes nodos del clúster.

Finalmente, la conversión de los resultados a CSV permite preparar la información anonimizada para su incorporación a MySQL, proporcionando una capa de persistencia estructurada que facilita las consultas, el análisis y la explotación posterior de los datos.
