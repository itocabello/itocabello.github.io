Tercer ejercicio resuelto con Hadoop Streaming - Agrupación del número de accidentes por provincia y mes a partir del conjunto de datos de la DGT de 2024.

Objetivo del ejercicio

Aplicar el modelo de programación MapReduce mediante Hadoop Streaming para calcular cuántos accidentes se registran en cada provincia y mes. El Mapper lee el CSV y emite una clave formada por provincia y mes, junto con el valor 1. Hadoop agrupa las claves y el Reducer suma los valores.

Interpretación: el cálculo cuenta filas del fichero como accidentes. Esto presupone que cada fila representa un accidente individual en el conjunto de datos utilizado.

2. Conjunto de datos

Se utiliza el fichero TABLA_ACCIDENTES_24.csv, separado por punto y coma (;). Entre sus campos se encuentran:

Campo Uso en el ejercicio
MES Mes en el que se produjo el accidente (índice 2 del CSV).
COD_PROVINCIA Código de la provincia (índice 5 del CSV), convertido a nombre mediante un diccionario.
ID_ACCIDENTE Identificador del accidente; se utiliza para reconocer y omitir la cabecera del CSV.

Ruta de entrada en HDFS empleada en el notebook:

/datasets/accidentes/csv/TABLA_ACCIDENTES_24.csv

3. Flujo de procesamiento

Entrada

Hadoop lee el CSV almacenado en HDFS y distribuye sus registros entre las tareas Map.

Mapper

Convierte el código provincial en nombre y emite provincia|mes → 1.

Reducer

Suma los valores de cada combinación de provincia y mes.

4. Mapper: preparar las claves

El Mapper analiza cada línea como un registro CSV, ignora la cabecera, obtiene el mes y el código provincial, y consulta el diccionario PROVINCIAS. El diccionario debe incluir los códigos utilizados por el fichero.

La salida intermedia tiene una clave compuesta, por ejemplo Madrid|1, y el valor 1. El diccionario completo se mantiene en el archivo mapper_accidentes.py.

5. Reducer: sumar accidentes

Hadoop Streaming ordena y agrupa las claves emitidas por el Mapper. El Reducer acumula los valores de cada clave y devuelve el nombre de la provincia, el mes y el total.

6. Ejecución con Hadoop Streaming

El trabajo se lanza desde el contenedor namenode o desde una celda de Jupyter Notebook. La opción -files distribuye ambos scripts a las tareas del clúster. 

!hdfs dfs -rm -r -f /datasets/accidentes/resultados/dgt_accidentes_provincia_mes

!hadoop jar /usr/local/hadoop/share/hadoop/tools/lib/hadoop-streaming-3.4.0.jar \\
    -files mapper_accidentes.py,reducer_accidentes.py \\
    -mapper "python3 mapper_accidentes.py" \\
    -reducer "python3 reducer_accidentes.py" \\
    -input /datasets/accidentes/csv/TABLA_ACCIDENTES_24.csv \\
    -output /datasets/accidentes/resultados/dgt_accidentes_provincia_mes
Importante: el directorio de salida debe estar libre antes de lanzar el trabajo. El comando de eliminación elimina únicamente la carpeta de resultados de este ejercicio; úsalo solo si no necesitas conservarla.

8. Conclusiones

  • Hadoop Streaming permite implementar las funciones Map y Reduce usando scripts Python sin necesidad de escribir clases Java para la lógica de procesamiento.
  • El Mapper prepara una clave por provincia y mes y genera una contribución unitaria por cada registro válido.
  • El Reducer agrega las contribuciones para obtener el número de accidentes por grupo.
  • La salida permite comparar la distribución mensual de los accidentes entre provincias. Los recuentos deben interpretarse teniendo en cuenta la definición y el contenido del conjunto de datos.
