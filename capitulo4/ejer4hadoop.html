Análisis mensual del número de accidentes registrados en Madrid y de las mediciones de contaminantes atmosféricos mediante scripts Python ejecutados en Hadoop.

Objetivo

El objetivo es combinar dos conjuntos de datos de distinta estructura mediante Hadoop Streaming: los accidentes de tráfico de la DGT de 2024 y las mediciones de calidad del aire de Madrid. El análisis agrupa los registros por mes y calcula, para cada magnitud, el número de accidentes y la media de las mediciones disponibles.

El cruce es temporal (por mes), no espacial ni causal: que dos variables correspondan al mismo mes no demuestra que la contaminación provoque accidentes.

Datos de entrada

Conjunto de datos Ruta HDFS utilizada Campos relevantes
Accidentes DGT 2024 /datasets/accidentes/csv/TABLA_ACCIDENTES_24.csv Mes y código de provincia
Calidad del aire de Madrid /dataset/calidad_aire_madrid/calidad_aire_madrid.csv Magnitud, mes y columnas horarias H01–H24

Para los accidentes se filtra el código provincial 28, correspondiente a Madrid. En el fichero de calidad del aire, el Mapper extrae las mediciones horarias y las agrupa por mes y código de magnitud.

Importante: las rutas se han tomado de la ejecución adjunta. Si se desea usar el fichero reducido de 20.000 registros, hay que cambiar la ruta de entrada al nombre exacto de ese fichero en HDFS.

Flujo de procesamiento

1

Mapper

Distingue el fichero de origen, filtra los accidentes de Madrid y emite pares clave-valor con el mes como clave.

2

Shuffle y sort

Hadoop agrupa los registros por mes y envía juntos al Reducer los datos de accidentes y calidad del aire.

3

Reducer

Suma los accidentes y calcula la media por magnitud a partir de la suma y el número de mediciones válidas.

Ejecución con Hadoop Streaming

Se elimina el directorio de salida anterior y se ejecuta un único trabajo con ambos ficheros de entrada:

!hdfs dfs -rm -r -f /datasets/accidentes/resultados/cruce_aire
                        
!hadoop jar /usr/local/hadoop/share/hadoop/tools/lib/hadoop-streaming-3.4.0.jar \
-files mapper_cruce.py,reducer_cruce.py \
-mapper "python3 mapper_cruce.py" \
-reducer "python3 reducer_cruce.py" \
-input /datasets/accidentes/csv/TABLA_ACCIDENTES_24.csv \
-input /dataset/calidad_aire_madrid/calidad_aire_madrid.csv \
-output /datasets/accidentes/resultados/cruce_aire

Para consultar la salida generada:

!hdfs dfs -cat /datasets/accidentes/resultados/cruce_aire/part-*

La ejecución adjunta finalizó correctamente con un Reducer. Los resultados se guardaron en HDFS en el directorio /datasets/accidentes/resultados/cruce_aire.

Interpretación y limitaciones

  • El recuento mensual de accidentes de Madrid coincide con el resultado obtenido en el ejercicio de accidentes por provincia y mes (por ejemplo, 1.145 en enero y 1.100 en febrero).
  • La media se calcula con todas las mediciones no vacías y no negativas que el Mapper acepta. La salida debe contrastarse con las reglas de validación de la fuente y con los códigos de validez de cada dato.
  • Las mediciones pueden proceder de distintas estaciones de Madrid. Por tanto, esta media agregada no debe interpretarse automáticamente como una media espacialmente representativa de toda la ciudad.
  • El cruce mensual es exploratorio y no permite establecer una relación causal entre contaminación y accidentes. Para ello serían necesarios análisis estadísticos adicionales y variables de control.

Conclusión

El ejercicio muestra cómo Hadoop Streaming puede procesar dos conjuntos de datos heterogéneos en una misma ejecución MapReduce. El Mapper normaliza ambos tipos de registros bajo una clave temporal común y el Reducer calcula indicadores mensuales que permiten una primera comparación entre accidentes y calidad del aire. La práctica refuerza el uso de HDFS, Python y el modelo MapReduce para analizar datos reales.
